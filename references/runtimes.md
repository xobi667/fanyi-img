# 宿主运行时适配

先检查当前会话实际提供的图片工具、参考图机制、输出落盘方式和并发限制。核心规则不得硬编码工具名、provider、模型、密钥、用户名或电脑路径。

本 skill 的确定性预检、manifest、Logo、联系表、重采样与安装脚本要求 Python 3.10+ 和 Pillow 9.1+；`install_skill.py` 会在安装前硬检查版本。宿主缺少依赖或版本过旧时先报告并按其正式扩展机制补齐，不能把脚本不可运行的技能冒充为可用。

## 通用映射

- `generate`：不传参考图。
- `edit`：只传当前 task 的 target；其他素材逐一声明角色。
- `localization`：默认必须传当前源图作为唯一 target reference，执行 `text_only_reference_edit`。不得因为宿主更擅长生图就省略参考图；纯重建必须已有绑定本次 manifest、当前 task 和源图哈希的任务级用户许可记录。
- 每个 attempt 只调用一次图片工具并至多生成一个候选；基础设施失败可以没有候选。不同 worker 的参考图、会话最近图片、prompt 和输出路径必须隔离，禁止串图。
- 宿主只提供近似原生画幅时，该结果只能作为 `base`；交付前必须在不拉伸主体的前提下适配为用户确认的准确比例。无法满足就报告限制，不得把近似比例登记为 success。
- 宿主没有参考编辑能力时，默认 localization 和需要保真的 edit 必须停止并说明，不能用纯生图冒充完成。只有当前 task 已经满足三次失败门槛并持有绑定本次 manifest/task/source/第三次失败的明确纯重建许可时，才可在生成型宿主执行显式 `pure_rebuild` 阶段；宿主能力不足本身不能代替失败记录或用户许可。

## Codex

- 使用当前会话提供的原生图片生成/编辑工具，并严格按实际 schema 传参。
- 本地 target 已有路径时使用本地参考路径机制；只有会话图片时，包含完成当前 task 所需的最少最近图片。
- 本地路径机制与会话最近图片机制不能同时误带无关目标。
- 工具返回结果后立即保存到 manifest 预分配路径并更新当前 task state。

## OpenClaw / Clawdbot

- 使用当前会话已暴露且配置完成的原生图片工具；工具名和参数以实际 schema 为准。
- 不指定固定 Gemini、Nano Banana、OpenAI API 或其他 provider。
- edit/localization 只有在工具明确支持时传当前 target。只返回远端附件时，使用宿主合法附件保存能力落入预分配路径；无法落盘就记录基础设施失败，不能伪造结果。

## 其他 AgentSkills 宿主

- 只有会话确实存在相应生成/参考编辑能力时执行。
- 将通用任务映射到实际 prompt、参考图和输出字段；不猜测不存在的参数。
- 能生成但不能参考编辑不代表可以自动降级 localization；必须遵守用户授权门槛。

## 并发契约

1. 工具/schema 明确禁止并发、只有一个图片槽位或共享会话状态不可隔离：直接 `workers=1`。
2. 工具允许并发：使用 `min(4, 可用槽位, task 数, 宿主上限)`。
3. 并发能力未知：默认最多 4；基础设施错误按 [quality.md](quality.md) 独立计数并在初次调用后最多重试 3 次（等待 2/5/10 秒）。出现两个 worker 同类限流、连接、附件或会话冲突时，取消尚未执行的并行退避重试并停止新派发。
4. 单路探针必须选一个原始 pending task，沿用该 task 的参考图、prompt 与隔离输出，并按实际结果计入它的质量或基础设施预算；不得发起无 task 归属的空探针。探针候选验收成功后把 manifest 标记为降级、设置 `workers=1` 并只补 pending；失败则停止。不得为了凑四路违反工具 schema。

## 交付

宿主支持附件时按原生方式交付；不支持时报告本地绝对路径。飞书、Discord、Telegram 等通道规则只在对应工具实际存在时适用，不能写入通用核心。无论宿主如何交付，原图只读、任务根目录最终成品和 `.xobi/` 元数据分离规则不变。
