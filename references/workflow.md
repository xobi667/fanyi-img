# 统一图片工作流

## 1. 模式判断

### generate

适用于没有需要保留的源图、从文字创建全新画面。提取主题、用途、画幅、风格、构图、色彩、光线和必须出现/禁止出现的元素。用户没给尺寸时使用内置默认尺寸，不为了“统一”擅自改成 800×800。

### edit

适用于任何已有图片的定向修改。先查看源图，记录：

- 原始像素与比例；
- 主体的形状、位置、朝向、颜色和材质；
- 背景、阴影、透视、光线与留白；
- 原有文字、Logo 和不得变化区域。

只修改用户点名的内容。未点名区域全部进入保持不变清单。

### localization

适用于图片文字翻译、改字或多语言本地化。它本质上是参考图编辑，不是脱离原图重新创作。必须先确认：

- 目标语言；
- 输出比例；
- 默认只翻译原有文字；只有用户明确要求新增或改写文案时才偏离，不把这一项作为额外必问；
- 若非 1:1，确认目标像素或让用户明确使用内置默认画幅。

默认行为：只替换源图中可见文字，保持商品、人物、背景、布局、品牌、促销结构和所有未指定内容。不得添加原图没有的标题、卖点、角标、品牌或装饰。

1:1 且沿用既有翻译交付规格时，最终可优化为 800×800 JPG、900–1024KB。非 1:1 不套用这条规则。

localization 专属前置条件：

- 目标语言和输出比例必须明确；只缺一项时只询问缺失项，两项都缺时一次问完。
- 非 1:1 且用户要求精确尺寸时，必须确认目标像素；普通 generate/edit 不受这条语言前置条件影响。
- 输出目录按目标语言区分，保持原文件名主体和相对目录结构；禁止覆盖原图，已有合格成品默认补缺。
- 无文字商品图、纯产品图、空白图或透明图只跳过文字翻译；用户要求比例转换或瑕疵修复时仍需处理，并必须保持完全无字。
- 1:1 任务的最终优化只在用户沿用既有交付规格时执行；保持原比例、透明输出或其他画幅不得被强制压成方形 JPG。

### batch

批量是 generate/edit/localization 的执行修饰：

- 一张输入图对应一个独立任务；
- 一次内置调用只处理一个独立成品或一个明确变体；
- 每张图单独建立参考图集合，避免跨图串内容；
- 多张图片共同合成一张图属于 edit，不属于 batch；
- 用户明确要求统一风格时才添加批次风格锁，否则逐图忠实处理。

可以安全并行且结果路径可控时，最多 4 个独立 worker；否则顺序执行。worker 数为 `min(4, 可用槽位数, 待处理数)`，每个 worker 内逐张处理。每个 `task_id` 只能归属一个 worker，只产生一个目标输出；prompt、文字锁、参考图和输出路径不得跨任务共享。失败图在当前 worker 内单独重试，不让已成功图片重跑；环境不支持并行或充分重试后仍持续出现基础设施错误时降为 1 路，沿用原任务清单补跑。

用户明确要求整批视觉统一时，在分配 worker 前建立并冻结 `<任务目录>/batch_style_lock.json`；用户未要求统一时，优先忠实保留各源图自身版式，不强制套模板。

## 2. 参考图传递

- 全新 generate：不传 `referenced_image_paths`，也不传 `num_last_images_to_include`。
- 本地 edit/localization：先查看图，再传 `referenced_image_paths`。
- 仅会话内有图：传最小必要的 `num_last_images_to_include`。
- 两种引用机制不能共存。
- 多图按角色排序并在提示词中写出每张图用途。

## 3. 尺寸与透明背景

- 普通 edit 默认保持源图尺寸或比例。
- 普通 generate 没有尺寸要求时使用内置默认。
- 用户明确给出比例或像素时，以其要求为准；后处理不得拉伸主体。
- 需要透明背景时先使用内置能力生成清晰单色隔离背景或透明意图；若要靠本地去色，只能做确定性离线处理。
- 禁止为了透明通道改用任何需要 key 的 CLI/API。无法稳定得到透明通道时，如实说明限制并提供不透明或纯色底成品选项。

## 4. 本地任务目录

可获得本地输出时建立：

`xobi/图片生成/YY/MM/DD/任务名-HHMMSS/`

单图任务按需包含；批量与 ZIP 任务必须实际包含：

- `source/`：只读源图副本或路径清单；
- `output/`：最终成品；
- `manifest.json`：原图、模式、角色、提示词摘要、输出和状态；
- `report.md`：输入数、应处理数、成功数、跳过数、失败数和失败原因。
- 用户要求统一时，还必须记录风格锁路径/版本、联系表路径、异常图片和重生结果。

不覆盖原图，不把临时图片落在工作空间根目录。

## 5. ZIP 输入、多变体与本地画廊

当用户提供 ZIP/压缩包，且其中主要是 `.jpg/.jpeg/.png/.webp` 图片时：

1. 解压到当前任务目录的 `source/`，忽略隐藏文件和系统元数据。
2. 统计全部有效图片；除非用户另有说明，默认逐张处理全部有效图片。
3. 每张图片使用独立参考图集合和独立输出，避免覆盖、错配和串图。
4. 输出文件保留原文件名主体，只在必要时增加短后缀防重名。
5. 在 `manifest.json` 写入原文件、处理模式、目标语言或修改项、输出文件和状态。
6. 核对输入数与应交付数，只把最终成品重新打包成新的 ZIP 并交付；`manifest.json`、`report.md`、`batch_contact_sheet.jpg`、原图和中间图默认排除，不能只回复本地路径。

当用户要求多个创意方向或指定数量的变体时：

- 每个变体分别调用一次 Codex 内置生图；
- 保存每个 prompt 与成品的映射，不能随机生成后丢失对应关系；
- 本地结果较多、用户需要集中挑选时，可生成纯本地 `index.html` 缩略图画廊；画廊只是预览，不替代原图交付；
- 画廊和映射不得引入 API、provider 或 key。

用户说 1K/2K/4K、横版/竖版、PNG/JPG/WebP、透明/不透明或质量高低时，把它视为输出要求；使用内置能力的最接近规格，并在需要精确像素或格式时做本地确定性后处理，不切换外部模型。

## 6. 批量视觉系统锁与联系表

用户明确要求整批视觉统一时：

1. 在第一张图生成前创建 `<任务目录>/batch_style_lock.json`，使用 UTF-8 原子写入，`content_isolation` 必须为 `true`。
2. 风格锁至少包含：`version`、`canvas`、`typography`、`layout`、`palette`、`label_style`、`product_scale_range`、`reference_source`、`content_isolation`。
3. 只允许保存抽象风格，不得写入单图译文、参数、商品内容或会话图片；worker 只读，修订由主协调者递增版本。
4. 每张图继续使用独立内容锁和参考图集合。统一视觉语言不等于复制其它图片的文字、商品或构图。
5. 全部单图质检通过后运行：

`python scripts/create_contact_sheet.py --input <最终输出目录> --output <最终输出目录>/batch_contact_sheet.jpg`

6. 查看联系表，横向检查字体、层级、对齐、边距、间距、色板、标签风格、商品尺度和形变。默认只重生偏离项；共享基准错误或用户明确要求时才整批重做。

## 7. localization 本地预检与优化

批量翻译可先运行：

`python scripts/preflight_fanyi.py --input <输入目录> --target-suffix <明确目标语言>`

不能依赖脚本的默认语言；目标语言必须来自用户请求。

只有明确采用 1:1 既有交付规格时，才运行最终优化：

`python scripts/final_optimize_images.py --input <输入目录> --output <输出目录>`

已有成品不合格需要重做时，加 `--overwrite`。普通生图、透明 PNG 或非 1:1 输出不要套用此优化。
