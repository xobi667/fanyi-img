# fanyi Workflow

## 目标语言和命名

根据用户表达确定目标语言：

```text
英语 / 英文 -> English -> 输出后缀：英语
泰语 / 泰文 -> Thai -> 输出后缀：泰语
印尼语 / 印尼文 / 印度尼西亚语 -> Indonesian -> 输出后缀：印尼语
越南语 / 越南文 -> Vietnamese -> 输出后缀：越南语
马来语 / 马来文 -> Malay -> 输出后缀：马来语
西班牙语 / 西语 -> Spanish -> 输出后缀：西班牙语
阿拉伯语 / 阿语 -> Arabic -> 输出后缀：阿拉伯语
```

强制规则：

- 目标语言是预检和生图前置必填项，不能根据文件夹名、文件名、历史任务、源图语言或商品品类推断。
- 用户未明确目标语言时，必须先问：`亲亲，请问需要翻译成什么语言？`
- 用户只提供文件夹/文件路径，且目标语言和比例都未明确时，一次性询问：`亲亲，请问需要翻译成什么语言，以及需要什么图片比例？例如 1:1、4:5、3:4、9:16，或者保持原比例。`
- 只缺目标语言时只问目标语言；只缺比例时只问比例。目标语言、比例和必要尺寸未全部确认前，不得运行预检、创建正式输出目录、分配 worker 或开始生图。
- 输出文件夹后缀必须和用户要求一致。
- 用户说泰语，输出目录必须是 `项目名-泰语`，prompt 必须要求 Thai。
- 用户说印尼语，输出目录必须是 `项目名-印尼语`，prompt 必须要求 Indonesian。
- 不允许出现“文件夹是泰语，但 prompt 还是 English”的错误。

## 输入模式

### 单张图片

如果用户给的是单张图片路径，仍然必须生图翻译。

- 默认最终输出到当前工作目录，文件名为 `原文件名-目标语言.jpg`。
- 原始生图结果可先保存为 `原文件名-目标语言-原始生图.png`。
- 如果用户指定输出目录或“放到当前根目录”，按用户要求。
- 不要只给文字翻译，除非用户明确说“只要文字”。
- 单张图片同样遵守目标语言、1:1、画质、边角、字体、单位、排版和最终优化规则。

### 整个文件夹

如果用户给的是文件夹，并说“翻译英语 / 翻译泰语 / 整个文件夹翻译 / 主图详情 sku 都翻译”等，必须批量处理。

默认目录：

```text
输入：E:\xxx\项目名称
输出：E:\xxx\项目名称-目标语言中文名
原始生图：E:\xxx\项目名称-目标语言中文名-原始生图
```

要求：

- 输出目录必须新建在输入目录同级。
- 默认最终输出目录保存优化后的 `.jpg` 成品；原始生图目录保存未压缩的中间结果。
- 不要把结果混到原文件夹。
- 不要覆盖原图。
- 如果输出目录已存在，默认补缺，不覆盖已有成功图片。
- 只有用户明确说“覆盖 / 重做 / 重新生成 / 全部重做”才覆盖。

## 目录结构和跳过规则

批量翻译时必须保持原结构。

```text
原项目/
  主图/1.jpg
  详情/a.png
  sku/SKU-01.jpg

原项目-英语/
  主图/1.jpg
  详情/a.jpg
  sku/SKU-01.jpg

原项目-英语-原始生图/
  主图/1.png
  详情/a.png
  sku/SKU-01.png
```

- 递归扫描整个输入文件夹。
- 支持图片扩展名：`.jpg .jpeg .png .webp .bmp .tif .tiff`。
- 每张图片都必须有对应最终 `.jpg` 输出；启用最终优化时，还应有对应原始生图中间文件。
- 非图片文件默认原样复制，以保持项目完整；如果用户说“只要图片”，才不复制非图片。
- 必须跳过已经生成的输出目录，避免重复翻译结果图。

跳过目录示例：

```text
*-英语
*-泰语
*-印尼语
*-越南语
*-马来语
*-西班牙语
*-阿拉伯语
*-原始生图
```

## 无文字和空白图片

无文字商品图、纯产品图、素材图、空白图、纯色图、透明图、无文案占位图只能跳过“文字翻译”，不能跳过“比例处理、瑕疵清理、最终优化”。

- 如果用户要求 `1:1`、方图、指定尺寸，无文字商品图/纯产品图/空白图也必须按该比例输出。
- 竖图、长图、拼接图、局部特写图在 1:1 任务中必须通过 Codex 图片编辑/生图整理成方图。
- 空白/无文字图片如果存在黑点、脏边、裁切残留、白边不整齐、透明边、压缩噪点、画布不完整、拼接线明显等瑕疵，仍然必须调用 Codex 修复。
- 只有当空白/无文字图片本身干净、比例已经合格、无需视觉修复时，才可以复制到原始生图目录作为中间文件；最终优化仍必须执行。

## 比例和尺寸

比例是生图前置必填项，不能默认推断。

- 用户未明确比例时，必须先问：`亲亲，请问需要什么图片比例？例如 1:1、4:5、3:4、9:16，或者保持原比例。`
- 用户已明确比例时直接执行，不重复确认。
- 用户选非 1:1 但未给目标像素尺寸时，继续询问目标尺寸；未确认前不得开始预检分片或生图。
- 用户明确 `保持原比例` 时，逐图保持各自原比例，并在最终优化阶段避免统一压成方图。

用户说以下内容时，按 1:1 处理：

```text
比例 1:1
必须 1比1
方图
主图方图
```

必须：

- 在 prompt 中明确要求输出为 square 1:1 e-commerce image。
- 可以通过 Codex 生图扩展/补全画面到 1:1，让背景、商品场景、边角更完整。
- 扩图只能扩展无文字的视觉画面，不能扩展文字、不能扩展 SVG 图标文字、不能新增卖点、不能新增标签。
- 批量完成后检查输出宽高是否相等。
- 不是 1:1 的图片必须列入重生清单并重新调用 Codex 生图。
- 无文字商品图、纯产品图、素材图、空白图、纯色图、透明图、无文案占位图也必须参与 1:1 检查。
- 不允许本地裁剪、拉伸、扩图、压缩来伪造成 1:1。

用户未指定比例时不得默认保持原图，也不得默认 1:1；必须先询问。

## 最终优化

默认必须在全部图片翻译、生图、质检完成之后，再统一执行最终优化。不要在每张图生图之后立刻压缩。

用户确认 1:1 时的默认目标：

```text
最终成品尺寸：800x800 px
最终成品格式：JPG
最终文件体积：900KB-1024KB
```

强制规则：

- 只有用户明确说“不压缩 / 不要最终优化 / 保留原尺寸原体积”时，才跳过最终优化。
- 最终优化只改变画布尺寸、图片编码质量和文件体积，不允许改写文字、不允许贴字、不允许新增卖点、不允许改变商品和版式含义。
- 用户确认 1:1 时默认输出为精确 `800x800` 白底画布；其他比例使用已确认尺寸。保持原图比例等比缩放放入画布，不裁剪、不拉伸、不变形。
- 如果源图有透明背景，默认合成到白底。
- 无文字商品图、纯产品图、素材图、空白图、纯色图、透明图、无文案占位图也必须进入最终优化。
- 已存在输出如果不是目标比例、目标尺寸、JPG 格式或体积区间，必须视为不合格并重新优化或重新生成。
- 如果输出高于 1024KB，降低 JPEG 质量，寻找不超过上限的最高画质。
- 如果输出低于 900KB，允许在 JPEG 文件尾部补无损填充字节，把文件体积补到 900KB 以上且不超过 1024KB；这不改变画面像素。
- 如果在 `800x800` 和最低 JPEG 质量下仍然超过 1024KB，记录为最终优化失败，不要继续缩小到非 800x800，除非用户明确允许。

推荐命令：

```text
python scripts/final_optimize_images.py --input RAW_OUTPUT_DIR --output OUTPUT_DIR --size 800x800 --min-kb 900 --max-kb 1024
```

## 推荐执行逻辑

1. 判断输入是单图还是文件夹。
2. 确认目标语言和输出后缀；未明确目标语言时先询问。
3. 确认输出比例；未明确时先询问。目标语言和比例都缺失时一次问完；非 1:1 且像素尺寸未明确时继续询问尺寸。
4. 判断覆盖、只补缺、只图片。
5. 批量任务先运行 `scripts/preflight_fanyi.py`。
6. 扫描文件，但跳过输出目录、原始生图目录和其他语言输出目录。
7. 创建原始生图目录和最终输出目录，并保持相对路径结构。
8. 非图片文件默认在最终优化阶段复制到最终输出目录。
9. 无文字商品图、纯产品图、素材图、空白图、纯色图、透明图、无文案占位图只能跳过文字翻译，不能跳过比例处理、瑕疵清理和最终优化。
10. 有文案/不确定图片默认走 Codex 生图，并把原始结果保存到 `RAW_OUTPUT_DIR`。
11. 查看当前源图并锁定商品、构图和文字后，使用简短 prompt 调用 Codex 直接纯生图；默认省略 `referenced_image_paths`。只有用户明确要求编辑原图时才使用参考图编辑。
12. 一般情况下默认使用 `MAX_WORKERS = 4`，不得超过 4。只有待处理任务不足 4 个时，worker 数才等于任务数。
13. 运行预检时传入 `--workers 4`，以报告中的 `task_id` 和 `worker_id` 为唯一分工清单。主协调者兼任 worker-1，另外启动 worker-2、worker-3、worker-4；四者同时处理互不重叠的任务。每个 worker 内一张一张处理，每次纯生图 prompt 只描述当前任务。
14. 失败自动重试，但必须在当前 worker 的当前图片内部完成至少 3 次重试；网络错误、超时和限流使用递增等待。单次失败不得立即降低并发，prompt、文字锁、输出路径和会话图片不得跨 worker 共享。
15. 如果运行环境明确不支持并行，或 4 路在充分重试后仍持续出现同类基础设施错误，直接降级为 `MAX_WORKERS = 1`，沿用原 task_id 清单逐张补跑，跳过已成功输出。
16. 所有 worker 完成后合并结果，验证每个 `task_id` 恰好有一个终态、一个 worker 归属和一个目标输出；发现重复领取、重复输出或遗漏时停止最终优化并修正清单。
17. 按用户确认的比例检查所有图片输出尺寸，无文字商品图/纯产品图/空白图也必须检查。
18. 翻译全部完成后，生成基础报告和失败清单。
19. 除非用户明确禁止最终优化，否则按确认尺寸运行 `scripts/final_optimize_images.py`。
20. 检查最终优化报告；1:1 默认确认 800x800 JPG、900KB-1024KB，其他比例确认用户指定尺寸。
