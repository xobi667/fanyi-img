# 图片质量验收

## 通用验收

每张成品至少检查：

- 是否完成用户要求的核心变化；
- 是否保持所有未指定区域；
- 主体是否完整、无多余肢体/部件、无畸变；
- 构图、边缘、透视、阴影、反射和光线是否合理；
- 是否出现未要求的文字、Logo、水印、角标或伪文字；
- 尺寸、比例、格式和透明通道是否符合明确要求；
- 原图是否仍完好且未被覆盖。

若本地已有成品，使用图片查看能力做视觉检查；不要只依赖文件存在和脚本返回码。

## 文字验收

- 精确文案逐字比对；
- 检查大小写、拼写、标点、数字、币种、单位和换行；
- 检查文字是否截断、重叠、乱码、重复或产生伪字；
- 用户未要求文字时，任何文字都视为缺陷。

## localization 专项

- 源图文字是否全部覆盖，译文是否自然且目标语言正确；
- 是否只翻译原有文字，没有自行增加卖点；
- 品牌、型号、数量、规格、货币和单位是否按规则保留；
- 商品几何、颜色、纹理、数量、人物、Logo、背景和版式是否发生漂移；
- 1:1 既有交付规格下，最终文件才检查 800×800 JPG、900–1024KB；其他画幅按用户要求检查。
- 建立当前图片文字锁：可见文字块清单、数量和大概位置。输出多出原图没有的文字块、参数栏、卖点栏、赠品、规格或角标时必须判定失败并重生。
- 对比商品纵横比、轮廓、厚薄、部件比例、材质和透视；检查文字字形、字距、行距、重叠、裁切、溢出和扭曲。任一明显形变均不能计入成功。

## 批量验收

批量完成后核对：

- 输入总数；
- 应处理数；
- 成功数；
- 跳过数及原因；
- 失败数及原因；
- 原图到成品一一映射；
- 是否存在覆盖、漏图、重复图、错配参考图或跨任务串图；
- `manifest.json` 和 `report.md` 是否真实存在，且记录与磁盘成品一致；
- ZIP 输入是否保留原文件名主体，并完成解压前、处理后和重新打包后的数量核对；交付 ZIP 默认只含最终成品，不得混入 `manifest.json`、`report.md`、`batch_contact_sheet.jpg`、原图或中间图；
- 多变体任务是否保存 prompt 到成品的一一映射。

不得只抽查一张就宣布整批完成。

## 批量隔离与完整性

- worker 数使用 `min(4, 可用执行槽位, 待处理图片数)`；每个 worker 内逐张串行。
- 每个 `task_id` 只能出现一次、归属一个 worker、产生一个目标输出；prompt、文字锁、参考图和输出路径必须隔离。
- 当前图片失败只在当前 worker 内重试；成功图片不得因补跑或降级而重做。
- 环境不支持并行或充分重试后仍持续出现同类基础设施错误时，降为 1 路，沿用原任务清单补跑。
- 全程只使用 Codex 内置生图，禁止任何 provider/API/CLI/key 回退。

## 用户要求统一时：整批横向质检

启用 `BATCH_STYLE_LOCK` 后，单图通过仍不能直接交付。必须运行并查看：

`python scripts/create_contact_sheet.py --input <最终输出目录> --output <最终输出目录>/batch_contact_sheet.jpg`

横向比较字体、层级、对齐、边距、间距、色板、标签/图标风格、商品自然视觉尺度和形变；同时确认没有新增文案、参数或串入其它图片内容。

- 明显偏离风格锁的图片必须失败并单独重生。
- 多数图片同向偏离时，由主协调者修订风格锁并递增版本。
- 默认只重生异常图；共享基准错误或用户明确要求时才整批重做。
- 报告记录风格锁路径与版本、联系表路径、一致性验收结果、异常文件和重生结果。

## 主图、详情图与 SKU 专项

- 主图：干净醒目，但不得为了主图效果新增卖点或装饰文字。
- 详情图：只处理原有说明，保持层级和可读性；不得添加原文没有的功能、参数或承诺。
- SKU：规格、型号、尺寸、颜色、厚度和数量以图中可见文字为准；文件名只用于输出命名，不能进入画面。

## 重试策略

- 对明确可修复的缺陷，收窄提示词后使用同一 Codex 内置能力重试。
- 每次重试记录具体失败点，不做无目标重抽。
- 失败图单独重试，成功图不重跑。
- 内置能力不可用、连续失败或所需参考图缺失时，停止并说明具体原因。
- 禁止切换 Gemini、OpenAI API、Nano Banana、第三方网关、CLI 或任何 key 型生图服务。

## 简短报告

需要文字报告时只写事实：

- 模式与目标；
- 成功/失败计数；
- 输出目录或交付方式；
- 未解决问题。
- 批量任务同时维护机器可读的 `manifest.json` 与人类可读的 `report.md`；记录 task、worker、源图、输出、变体 prompt 摘要、状态、失败原因，以及可选的风格锁版本和 ZIP 数量核对。

最终一次内置生图调用之后遵守工具交付规则，不追加图片复述、下载提示或追问。
